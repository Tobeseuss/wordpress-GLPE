## 🇮🇷 معرفی

**GLPE Viewer** افزونه‌ای برای وردپرس است که امکان نمایش صفحات وب دلخواه را درون سایت شما فراهم می‌کند و به‌طور خاص برای **هاست‌های رایگان و اشتراکی** (فقط PHP، بدون دسترسی روت، بدون سرویس خارجی) طراحی شده است.

### 🔒 اصل پایه — مخفی‌سازی و کدگذاری کامل تبادلات
از نسخه ۵.۰.۰ این قاعده به‌صورت اصل تغییرناپذیر پروژه است:

> هیچ نشانی وب‌سایت یا محتوای بارگذاری‌شده‌ای بدون مخفی‌سازی و کدگذاری در تبادل‌های میان مرورگر و سرور منتقل نمی‌شود؛ نمایش نشانی در مرورگرِ خودِ کاربر اشکالی ندارد، اما این نشانی به هیچ عنوان نباید به‌صورت کدنشده در تبادلات میان مرورگر و سرور سفر کند. تمام محتوای صفحات نمایش‌داده‌شده صرفاً از دروازه عبور می‌کند و هیچ منبعی مستقیم بارگذاری نمی‌شود.

به این ترتیب اجرا شده است:
- **نشانی مقصد در هیچ آدرسی خوانا نیست** — همه پیوندها به توکن مات (`l=…`) با کلید اختصاصی هر نصب تبدیل می‌شوند؛ حالت اختیاری Short Links حذف شد چون دیگر چیزی «اختیاری» نیست.
- **فرم‌های GET کدگذاری‌شده** — کل پرس‌وجو (مقصد + فیلدهای کاربر) درون یک توکن سفر می‌کند؛ فیلدها در نوار آدرس/لاگ خوانا نیستند.
- **فرم‌های POST کدگذاری‌شده** — بدنه فرم‌های urlencoded درون پاکت توکن (`d=…`) ارسال می‌شود؛ فرم‌های دارای فایل به‌صورت بومی عبور می‌کنند (مقصد همچنان توکن است).
- **هیچ منبعی مستقیم بارگذاری نمی‌شود** — حذف `base`، حذف `ping`/`integrity`، بازنویسی `formaction` و `data` و رویدادهای درون‌خطی و srcdoc؛ جلوگیری از اتصال سوکت خارجی از سمت مرورگر.
- **حتی پیکربندی داخلی** (نشانی فعلی در ctx) هم با توکن ارسال می‌شود؛ صفحه خطا هم نشانی خوانا نشان نمی‌دهد.
- **نمایش محلی نشانی فعلی (v5.1.0)** — نشانی صفحهٔ فعلی در نوار ناوبری فقط سمت مرورگر و از روی توکنِ از پیش موجود در نوار آدرس بازسازی می‌شود؛ رشتهٔ بازسازی‌شده هرگز به سرور ارسال نمی‌شود و سرور نیز هیچ نشانی خوانایی در HTML تولید نمی‌کند.
- **سازگاری با صفحات بدون‌گیومه و اپ‌های SPA (v5.2.0)** — ویژگی‌های HTML بدون گیومه (`script src=//cdn.../app.js`) پیش از بازنویسی استاندارد می‌شوند؛ مشخص‌کننده‌های import ماژول‌ها و رشته‌های `//host` داخل JS سمت سرور بازنویسی می‌شوند (لودر ماژول مرورگر هوک کلاینت نمی‌پذیرد)؛ مسیر مقصد فقط محلی در نوار آدرس جای می‌گیرد تا روترهای React/Vue/Angular کار کنند — هاست و پارامترها همچنان فقط درون توکن مات سفر می‌کنند.
- **استثنای مستند واحد**: پخش‌کننده رسمی یوتیوب (embed) برای پخش ویدیو/تبلیغات یوتیوب.
- محدودیت شفاف: با غیرفعال‌بودن جاوااسکریپت در مرورگر، فیلدهای فرم‌های GET به‌صورت متنی ارسال می‌شوند (نشانی مقصد همچنان توکن است).

### معماری (چرا توسط هاست‌ها مزاحم‌ساز نمی‌شود؟)
- 🧩 **ترافیک از لایه استاندارد وردپرس** — تمام درخواست‌های خروجی از `wp_remote_request()` (WordPress HTTP API) ارسال می‌شوند؛ دقیقاً همان مسیری که هسته، قالب و افزونه‌ها برای به‌روزرسانی استفاده می‌کنند. تابع‌های خام کلاینت فقط به‌عنوان لایه پشتیبان باقی مانده‌اند.
- 🔤 **بدون واژه‌های حساس** — هیچ‌جای کد، نام فایل‌ها، نام کلاس‌ها، پارامترهای URL و کامنت‌ها، الگوهای آشکار (proxy / glype / browse.php / bypass / …) وجود ندارد. اسکریپت `tools/guard.sh` این موضوع را در CI به‌صورت خودکار کنترل می‌کند.
- 🔐 **کلید اختصاصی هر سایت** — پیوندهای کوتاه با کلید تصادفی تولیدشده هنگام فعال‌سازی کدگذاری می‌شوند؛ هر نصب کلید مخصوص خودش را دارد.
- 🍪 **نشست جداگانه سمت سرور** — داده‌های نشست هر سایت مقصد داخل PHP Session نگهداری می‌شود.
- 📦 **بدون وابستگی خارجی** — نه Composer، نه npm، نه فونت/CDN بیرونی.

### ویژگی‌ها
- بازنویسی کامل HTML/CSS/JS (پیوندها، فرم‌ها، تصاویر، srcset، data-attributes، SVG، iframe)
- ⚡ **تثبیت DNS و سرعت اتصال (v6.1)** — کش ماندگار نشانی‌ها + مسیر یدکی DoH با پایانه‌های ثابت (۱.۱.۱.۱ و ۸.۸.۴.۴)؛ خطای «Resolving timed out» هاست‌های اشتراکی به‌صورت خودکار با نشانی تازه ترمیم می‌شود، بدون آنکه هیچ نشانی خوانایی در تبادلات ظاهر شود
- هوک سمت کلاینت: `fetch`، `XHR`، `document.cookie`، `window.open`، `history.pushState` + MutationObserver برای محتوای داینامیک
- نوار ناوبری شناور با گزینه‌های زنده و نمایش محلی نشانی صفحهٔ فعلی
- 📡 **هسته ارتباطی چندگرهی (v6)** — سیستم ضدسانسور چندگرهی داخل افزونه (توضیح در ادامه)
- محافظت آدرس‌های داخلی (دو لایه: کنترل داخلی + `reject_unsafe_urls` وردپرس)
- سه لایه انتقال: WordPress HTTP API → cURL → Streams
- گزینه‌های کم‌مصرف: بدون تصاویر / بدون اسکریپت برای کاهش پهنای باند
- شورت‌کد `[glpe_viewer]` + برگه خودکار `/view/` + صفحه تنظیمات در پیشخوان
- 🔐 سطح دسترسی «مرورگر GLPE» — فقط کاربران دارای مجوز یا مدیران می‌توانند از نمایشگر استفاده و وارد شوند؛ مدیریت مجوز نقش‌ها و کاربران از پیشخوان
- 🍪 مدیریت نشست‌ها توسط کاربر — هر کاربر می‌تواند کوکی‌ها و نشست‌های ذخیره‌شده خودش را به‌تفکیک دامنه ببیند و پاک کند (`?_glpe=1&mode=sessions` + لینک از ویجت)
- حذف کامل داده‌ها هنگام حذف افزونه (`uninstall.php`)

### 📡 هسته ارتباطی چندگرهی (Multi-Node Relay Core — v6.2.0)
از نسخه ۶.۰.۰ یک سیستم تونل‌زنی شبکه ضدسانسور به‌طور کامل داخل افزونه ادغام شده است:

- **هر سایت وردپرسیِ نصب‌کننده یک گره (node) است** — موتور سمت سرور (`includes/Hub.php`) درخواست‌های کپسوله‌شده کلاینت را روی نقطه پایه سایت (home_url) پاسخ می‌دهد؛ هیچ فایل اضافی یا مسیر ویژه‌ای لازم نیست و فعال/غیرفعال کردن از یک کلید در پیشخوان انجام می‌شود
- **کلاینت Python کنسولی همراه افزونه** (`hub-client/client.py` + دو فایل GeoSite/GeoIP): ترافیک TCP و UDP را در قالب درخواست‌های عادی GET/POST کپسوله می‌کند، پیش‌خوان محلی SOCKS5 + HTTP روی پورت ۴۱۹۲۷ ارائه می‌دهد و بین چند گره (هر سایت نصب‌کننده) به‌صورت چرخشی توزیع بار با failover خودکار انجام می‌دهد
- **مبهم‌سازی سیمی**: تمام پاکت‌ها در پارامتر `_v` (JSON → Base64 → معکوس) سفر می‌کنند و بارهای دانلود/آپلود هم معکوس‌Base64 هستند — هیچ نشانی، کلید یا محتوایی به‌صورت خوانا روی خط دیده نمی‌شود
- **ویژگی‌های عملیاتی**: پرکنندهٔ ۲۰۴۸ بایتی برای شکستن بافر CDN + `X-Accel-Buffering: no`، واچ‌داگ دوگانهٔ کلاینت با مصونیت VIP برای جریان‌های فعال (>۱۰KB/s)، تأخیر تطبیقی، مسیریابی مستقیم GeoSite/GeoIP برای شبکهٔ داخل ایران، پاکسازی دیسک با Lock-File، نگهدارنده متریک‌های محدود و پایش زنده در پیشخوان (آژاکس هر ۲ ثانیه)
- **رفع ریشه‌ای نسبت به طراحی مستقل اولیه**: پاکت‌های دارای «+» دیگر خراب نمی‌شوند (بازگردانی بی‌اتلاف فاصله↔+ در موتور + URL-encode کامل در کلاینت)، دادهٔ اولیهٔ تونل (ClientHello) دیگر در شروع جریان پاک نمی‌شود، و تونل‌های بی‌صدا با keepalive هر ۲ ثانیه ورکرها را آزاد نگه می‌دارند (رفع مشکل زامبی/Deadlock سمت سرور)
- **مسیر سریع گره (`hub-endpoint.php`)** — نقطه پایهٔ مستقل که بدون بوت سیستم مدیریت محتوا به پروتکل `_v` پاسخ می‌دهد (ده‌ها میلی‌ثانیه به‌جای ۱ تا ۷ ثانیه)؛ کلاینت خودکار بین مسیر سریع و مسیر وردپرسی جابه‌جا می‌شود (`fallback_url`) و کلید/وضعیت فعال‌بودن گره در یک فایل واگذاری محافظت‌شده (`<?php exit; ?>` + JSON) نگهداری و هم‌زمان با تنظیمات هم‌گام می‌شود
- **مدیریت**: صفحهٔ اختصاصی «هستهٔ ارتباطی چندگرهی» در پیشخوان (زیرمنوی مستقل افزونه) — وضعیت گره و هر دو مسیر، کلید و ساخت کلید جدید، پایش زنده، دانلود config.json آماده و بستهٔ کلاینت (ZIP یا فایل به‌فایل برای هاست‌های بدون ZipArchive) و فرم کامل ویرایش همهٔ مقادیر کانفیگ کلاینت
- **ارزیابی عملی هاست + کالیبراسیون همزمانی + ذخیرهٔ خودکار**: یک دکمه، سنجش واقعی روی همین هاست انجام می‌دهد — مشخصات PHP، پاسخ‌دهی هر دو مسیر گره، اتصال خروجی TCP، استریم، DNS سیستم و دو پایانهٔ DoH، خروجی 443 و دسترسی به دو سایت نمونه — و سپس **کالیبراسیون همزمانی**: چندین اتصال به‌صورت دسته‌ای و هم‌زمان با هاست برقرار می‌شود و به‌محض دیدن خطای 503 اندازهٔ دسته‌ها خودکار کم می‌شود تا بزرگ‌ترین دستهٔ بدون خطا پیدا شود (زمان پاسخ هر دسته، تعداد کارگر مؤثر هاست را هم لو می‌دهد). همهٔ مقادیر پیدا‌شده — سقف کانال‌های گره، استخر کلاینت، تایم‌اوت‌ها و تنظیمات DNS مرورگر GLPE — **بدون نیاز به هیچ دکمهٔ ذخیره‌ای خودکار ثبت می‌شوند**
- **🛠 رابط تشخیص از راه دور (v6.3.0)**: برای مشکلاتی مثل پاسخ 403 هاست به پایانه‌های گره که فقط از درون هاست قابل شناسایی‌اند — کارت «رابط تشخیص از راه دور» در تنظیمات اصلی، کلید کامل اتصال (آدرس + کلید دسترسی) می‌سازد تا به دستیار مورد اعتماد داده شود؛ پایانهٔ مستقل `diag-endpoint.php` بدون بوت وردپرس محیط سرور، پروفایل وردپرس، بازارسال کنترل‌شدهٔ درخواست‌های مسدودشده (تغییر هویت/روش/مسیر درون‌سرور)، فایل‌های .htaccess، گزارش‌های خطا و امکان اصلاح تنظیمات با فهرست سفید را ارائه می‌دهد؛ هر تغییر راه دور در ژورنال حسابرسی ثبت و به مدیر نمایش داده می‌شود (کلید نادرست: 404 خاموش؛ ۱۰ تلاش ناموفق: قفل ۳۰ دقیقه)
- **🛡 بقا در برابر قوانین لبهٔ هاست (v6.4.0 — تشخیص زنده روی یک هاست رایگان واقعی)**: لبهٔ openresty دو قانون پنهان داشت که هر دو پایانهٔ گره و کل کلاینت را از کار می‌انداخت: (۱) درخواست‌های با هویت پیش‌فرض CMS قبل از اجرای PHP با 403 خام رد می‌شوند؛ (۲) درخواست‌های خارجی پشت چالش کوکی جاوااسکریپت (صفحهٔ AES) می‌روند. اکنون: تمام درخواست‌های خودِ گره با هویت کامل مرورگر ارسال می‌شوند (هر دو مسیر + کالیبراسیون دوباره کار می‌کنند) و هستهٔ پایتون چالش AES-128-CBC را **بدون مرورگر و بدون وابستگی جدید** حل می‌کند — نشست هر گره قبل از ترافیک آماده‌سازی می‌شود، هر ساعت تازه‌سازی می‌گردد، POSTهای نوشتن در صورت چالش بازارسال می‌شوند و استریم خواندن بازیابی می‌شود؛ به‌علاوه نشانی گره وردپرسی با طرح زندهٔ سایت ساخته می‌شود (رفع مرگ در ریدایرکت نصب‌های TLS پروکسی) و فیلدهای کانفیگ قابل‌ویرایش سقف عددی گرفتند
- **محافظ هاست در برابر بار بیش از حد**: سقف کانال‌های همزمان روی گره (پیش‌فرض ۶، ۲ تا ۳۲) — هر کانال زنده یک کارگر PHP را تا پایان اتصال نگه می‌دارد؛ درخواست‌های بیش از سقف با 503 + Retry-After پاسخ داده می‌شوند و کلاینت مؤدبانه و بدون جریمهٔ گره تلاش مجدد می‌کند
- شروع سریع: دانلود بستهٔ کلاینت → `pip install requests` → `python client.py` → اتصال مرورگر/سیستم به `SOCKS5 127.0.0.1:41927` — برای افزودن گرهٔ دیگر، نشانی و کلید آن را از پنل همان سایت بردارید و به آرایهٔ `servers` در config.json اضافه کنید

### نصب
1. از بخش [Releases](https://github.com/Tobeseuss/wordpress-GLPE/releases) فایل `glpe-viewer-x.y.z.zip` را دانلود کنید.
2. وردپرس → **افزونه‌ها → افزودن → بارگذاری افزونه** و فایل ZIP را نصب کنید.
3. افزونه را فعال کنید — برگه نمایشگر در `yoursite.com/view/` ساخته می‌شود.
4. یا شورت‌کد `[glpe_viewer]` را در هر برگه/المنتور قرار دهید.

## 🇬🇧 Overview

**GLPE Viewer** turns a WordPress site into a remote page display tool, purpose-built for **free/shared hosting** — plain PHP only, no root, no external services.

### Why it coexists nicely with restrictive hosts
- All outbound fetching goes through **WordPress' own HTTP API** (`wp_remote_request`) — the same transport core uses for updates, so outbound traffic looks like ordinary WordPress activity.
- **No flagged vocabulary anywhere** in code, filenames, class names, query params or comments (`tools/guard.sh` enforces this in CI).
- **Per-install codec key** — short links are encoded with a random secret generated at activation, unique per site.
- Session data lives server-side in the PHP session; nothing sensitive is exposed client-side.
